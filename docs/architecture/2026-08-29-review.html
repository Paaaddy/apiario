One deep module. Two thin callers cross the same seam.

Problem: the hook's interface doesn't cover the aggregations callers need, so two callers route around it instead of through it.

Solution: widen the hook's interface with latestByColony and getLatestOverall(); delete the two local reimplementations.

  • Locality: one sort algorithm, fixed once
  • Leverage: memoized aggregation reused, not recomputed
  • "Latest" becomes one testable pure function

4. Route themes A/C through the existing CSS-variable seam

Speculative local-substitutable

src/screens/DiagnoseScreen.jsx · SeasonScreen.jsx · BottomNav.jsx (theme branches)

flowchart LR
  A[Theme A branch] -.leak.-> H[hardcoded hex/px]
  C[Theme C branch] -.leak.-> H
  B[Theme B branch] --> V[--theme-* CSS vars]
  V --> Tokens[data-theme attribute]
  classDef leak stroke:#c8351f,stroke-width:2px;
  class A,C,H leak

Problem: a seam already exists (--theme-* vars); two of three theme adapters bypass it with inline hex, duplicated per node-type branch.

Solution: route theme A/C's per-node tokens through the same CSS variables theme B already uses.

  • Locality: one CSS edit instead of per-screen inline edits
  • Leverage: new screens inherit theme C for free
No ADR names this seam as intentional yet — worth a domain-modeling pass before touching render code, since the pattern is systemic, not local to one file.

Top recommendation

Candidate 1 — collapse the latest-inspection reimplementations

Smallest, safest cut — pure logic move, no rendering risk — and it's the one with a real correctness angle: three divergent sort/compare implementations for the same fact silently disagree the moment only one gets edited. Establishes "hook owns aggregation, screens consume," a pattern this codebase is otherwise missing.
